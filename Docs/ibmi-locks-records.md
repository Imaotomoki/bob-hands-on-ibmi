# IBM i ロック・レコード管理サービス

このドキュメントは、IBM i のオブジェクト・ロックとレコード・ロックに関連するシステムサービスについて説明します。

## OBJECT_LOCK_INFO ビュー

OBJECT_LOCK_INFO ビューは、オブジェクトに対するロック情報を返します。

**権限:** 不要。

**主要カラム:**

| カラム名 | システムカラム名 | データ型 | 説明 |
| --- | --- | --- | --- |
| OBJECT_SCHEMA | OSCHEMA | VARCHAR(128) | オブジェクトを含むスキーマの名前 |
| OBJECT_NAME | NAME | VARCHAR(128) | オブジェクトの名前 |
| SYSTEM_OBJECT_SCHEMA | SYS_DNAME | VARCHAR(10) | オブジェクトのシステム・ライブラリー名 |
| SYSTEM_OBJECT_NAME | SYS_ONAME | VARCHAR(10) | オブジェクトのシステム名 |
| SYSTEM_TABLE_MEMBER | SYS_MNAME | VARCHAR(10) | ロックされているメンバーの名前 |
| OBJECT_TYPE | OBJTYPE | VARCHAR(8) | ロックされたオブジェクトのシステム・オブジェクト・タイプ |
| SQL_OBJECT_TYPE | SQLTYPE | VARCHAR(9) | オブジェクトの SQL タイプ |
| MEMBER_LOCK_TYPE | LOCK_TYPE | VARCHAR(10) | 保持されているロックのタイプ（ACCESSPATH、DATA、MEMBER） |
| LOCK_STATE | LOCK_STATE | VARCHAR(7) | ロック条件（*EXCL、*EXCLRD、*SHRNUP、*SHRRD、*SHRUPD） |
| LOCK_STATUS | STATUS | VARCHAR(9) | ロックの状態（HELD、REQUESTED、WAITING） |
| LOCK_SCOPE | LOCK_SCOPE | VARCHAR(10) | ロックのスコープ（JOB、LOCK SPACE、THREAD） |
| JOB_NAME | JOB_NAME | VARCHAR(28) | 修飾ジョブ名 |
| THREAD_ID | THREAD_ID | BIGINT | ロックに関連付けられたスレッド |
| LOCK_COUNT | LOCK_COUNT | INTEGER | 保持されている同一ロックの数 |
| PROGRAM_NAME | PROGNAME | VARCHAR(10) | ロックを保持しているプログラムの名前 |

### ロック状態の説明

- **\*EXCL**: 排他、読み取り不可
- **\*EXCLRD**: 排他、読み取り許可
- **\*SHRNUP**: 共用、更新不可
- **\*SHRRD**: 共用、読み取り可
- **\*SHRUPD**: 共用、更新可

### 使用例

```sql
-- 特定のオブジェクトのロック情報を表示
SELECT * FROM QSYS2.OBJECT_LOCK_INFO
WHERE OBJECT_NAME = 'MYFILE' AND OBJECT_SCHEMA = 'APPLIB';

-- すべての排他ロックを表示
SELECT OBJECT_SCHEMA, OBJECT_NAME, LOCK_STATE, LOCK_STATUS,
       JOB_NAME, PROGRAM_NAME
FROM QSYS2.OBJECT_LOCK_INFO
WHERE LOCK_STATE IN ('*EXCL', '*EXCLRD')
ORDER BY OBJECT_SCHEMA, OBJECT_NAME;

-- ロック待機中のジョブを特定
SELECT JOB_NAME, OBJECT_SCHEMA, OBJECT_NAME, 
       LOCK_STATE, LOCK_STATUS
FROM QSYS2.OBJECT_LOCK_INFO
WHERE LOCK_STATUS = 'WAITING'
ORDER BY JOB_NAME;

-- 特定のジョブが保持しているロックを表示
SELECT OBJECT_SCHEMA, OBJECT_NAME, OBJECT_TYPE,
       LOCK_STATE, LOCK_COUNT
FROM QSYS2.OBJECT_LOCK_INFO
WHERE JOB_NAME = '123456/QUSER/QZDASOINIT'
  AND LOCK_STATUS = 'HELD'
ORDER BY OBJECT_SCHEMA, OBJECT_NAME;

-- ライブラリー別のロック数を集計
SELECT OBJECT_SCHEMA, 
       COUNT(*) AS LOCK_COUNT,
       SUM(CASE WHEN LOCK_STATUS = 'WAITING' THEN 1 ELSE 0 END) AS WAITING_COUNT
FROM QSYS2.OBJECT_LOCK_INFO
GROUP BY OBJECT_SCHEMA
ORDER BY LOCK_COUNT DESC;
```

## RECORD_LOCK_INFO ビュー

RECORD_LOCK_INFO ビューは、レコード・ロックに関する情報を返します。

**権限:** 不要。

**主要カラム:**

| カラム名 | システムカラム名 | データ型 | 説明 |
| --- | --- | --- | --- |
| TABLE_SCHEMA | TABSCHEMA | VARCHAR(128) | スキーマの名前 |
| TABLE_NAME | TABNAME | VARCHAR(128) | テーブルの名前 |
| TABLE_PARTITION | TABPART | VARCHAR(128) | ロックされたレコードを含むメンバーの名前 |
| SYSTEM_TABLE_SCHEMA | SYS_DNAME | VARCHAR(10) | スキーマのシステム名 |
| SYSTEM_TABLE_NAME | SYS_TNAME | VARCHAR(10) | テーブルのシステム名 |
| SYSTEM_TABLE_MEMBER | SYS_MNAME | VARCHAR(10) | メンバーの名前 |
| RELATIVE_RECORD_NUMBER | RRN | BIGINT | ロックされているレコードの相対レコード番号 (RRN) |
| LOCK_STATE | LOCK_STATE | VARCHAR(8) | レコードのロック条件（READ、UPDATE、INTERNAL） |
| LOCK_STATUS | STATUS | VARCHAR(9) | ロックの状態（HELD、WAITING） |
| LOCK_SCOPE | LOCK_SCOPE | VARCHAR(10) | ロックのスコープ（JOB、THREAD、LOCK SPACE） |
| JOB_NAME | JOB_NAME | VARCHAR(28) | 修飾ジョブ名 |
| THREAD_ID | THREAD_ID | BIGINT | ロックに関連付けられたスレッド |

### レコード・ロック状態の説明

- **READ**: レコードは読み取り用にロックされている
- **UPDATE**: レコードは更新インテントでロックされている
- **INTERNAL**: 行は読み取りのために内部的にロックされている

### 使用例

```sql
-- レコード・ロック情報を表示
SELECT * FROM QSYS2.RECORD_LOCK_INFO;

-- 特定のテーブルのレコード・ロックを表示
SELECT TABLE_SCHEMA, TABLE_NAME, TABLE_PARTITION,
       RELATIVE_RECORD_NUMBER, LOCK_STATE, LOCK_STATUS,
       JOB_NAME
FROM QSYS2.RECORD_LOCK_INFO
WHERE TABLE_NAME = 'CUSTOMER' AND TABLE_SCHEMA = 'APPLIB'
ORDER BY RELATIVE_RECORD_NUMBER;

-- レコード・ロック待機中のジョブを特定
SELECT JOB_NAME, TABLE_SCHEMA, TABLE_NAME,
       RELATIVE_RECORD_NUMBER, LOCK_STATE
FROM QSYS2.RECORD_LOCK_INFO
WHERE LOCK_STATUS = 'WAITING'
ORDER BY JOB_NAME;

-- テーブル別のレコード・ロック数を集計
SELECT TABLE_SCHEMA, TABLE_NAME,
       COUNT(*) AS LOCKED_RECORDS,
       SUM(CASE WHEN LOCK_STATE = 'UPDATE' THEN 1 ELSE 0 END) AS UPDATE_LOCKS,
       SUM(CASE WHEN LOCK_STATUS = 'WAITING' THEN 1 ELSE 0 END) AS WAITING_LOCKS
FROM QSYS2.RECORD_LOCK_INFO
GROUP BY TABLE_SCHEMA, TABLE_NAME
ORDER BY LOCKED_RECORDS DESC;

-- 特定のジョブが保持しているレコード・ロックを表示
SELECT TABLE_SCHEMA, TABLE_NAME, RELATIVE_RECORD_NUMBER,
       LOCK_STATE, LOCK_SCOPE
FROM QSYS2.RECORD_LOCK_INFO
WHERE JOB_NAME = '123456/QUSER/QZDASOINIT'
  AND LOCK_STATUS = 'HELD'
ORDER BY TABLE_SCHEMA, TABLE_NAME, RELATIVE_RECORD_NUMBER;
```

## ロック競合の分析

### オブジェクト・ロック競合の検出

```sql
-- ロック競合が発生しているオブジェクトを特定
SELECT OBJECT_SCHEMA, OBJECT_NAME,
       COUNT(DISTINCT JOB_NAME) AS JOB_COUNT,
       SUM(CASE WHEN LOCK_STATUS = 'WAITING' THEN 1 ELSE 0 END) AS WAITING_COUNT,
       SUM(CASE WHEN LOCK_STATUS = 'HELD' THEN 1 ELSE 0 END) AS HELD_COUNT
FROM QSYS2.OBJECT_LOCK_INFO
GROUP BY OBJECT_SCHEMA, OBJECT_NAME
HAVING COUNT(DISTINCT JOB_NAME) > 1
ORDER BY WAITING_COUNT DESC, JOB_COUNT DESC;
```

### レコード・ロック競合の検出

```sql
-- 同じレコードに対する複数のロックを検出
SELECT TABLE_SCHEMA, TABLE_NAME, RELATIVE_RECORD_NUMBER,
       COUNT(*) AS LOCK_COUNT,
       LISTAGG(JOB_NAME, ', ') WITHIN GROUP (ORDER BY JOB_NAME) AS JOBS
FROM QSYS2.RECORD_LOCK_INFO
GROUP BY TABLE_SCHEMA, TABLE_NAME, RELATIVE_RECORD_NUMBER
HAVING COUNT(*) > 1
ORDER BY LOCK_COUNT DESC;
```

### ロック保持時間の監視

```sql
-- 長時間ロックを保持しているジョブを特定
-- (JOB_INFO と組み合わせて使用)
SELECT O.JOB_NAME, O.OBJECT_SCHEMA, O.OBJECT_NAME,
       O.LOCK_STATE, O.LOCK_COUNT,
       J.JOB_STATUS, J.FUNCTION, J.CPU_TIME
FROM QSYS2.OBJECT_LOCK_INFO O
JOIN TABLE(QSYS2.JOB_INFO(JOB_STATUS_FILTER => '*ACTIVE')) J
  ON O.JOB_NAME = J.JOB_NAME
WHERE O.LOCK_STATUS = 'HELD'
  AND J.CPU_TIME > 60000  -- 60秒以上
ORDER BY J.CPU_TIME DESC;
```

## デッドロックの検出

```sql
-- 相互にロック待機しているジョブを検出
WITH LOCK_WAIT AS (
  SELECT JOB_NAME, OBJECT_SCHEMA, OBJECT_NAME
  FROM QSYS2.OBJECT_LOCK_INFO
  WHERE LOCK_STATUS = 'WAITING'
),
LOCK_HELD AS (
  SELECT JOB_NAME, OBJECT_SCHEMA, OBJECT_NAME
  FROM QSYS2.OBJECT_LOCK_INFO
  WHERE LOCK_STATUS = 'HELD'
)
SELECT W1.JOB_NAME AS WAITING_JOB,
       W1.OBJECT_SCHEMA AS WAITING_FOR_OBJECT,
       H1.JOB_NAME AS HOLDING_JOB,
       W2.OBJECT_SCHEMA AS ALSO_WAITING_FOR
FROM LOCK_WAIT W1
JOIN LOCK_HELD H1 
  ON W1.OBJECT_SCHEMA = H1.OBJECT_SCHEMA 
  AND W1.OBJECT_NAME = H1.OBJECT_NAME
JOIN LOCK_WAIT W2 
  ON H1.JOB_NAME = W2.JOB_NAME
JOIN LOCK_HELD H2 
  ON W2.OBJECT_SCHEMA = H2.OBJECT_SCHEMA 
  AND W2.OBJECT_NAME = H2.OBJECT_NAME
  AND H2.JOB_NAME = W1.JOB_NAME
WHERE W1.JOB_NAME <> H1.JOB_NAME;
```

## ロック管理のベストプラクティス

### 1. 定期的なロック監視

```sql
-- ロック状況のサマリーを作成
SELECT 
  'Object Locks' AS LOCK_TYPE,
  COUNT(*) AS TOTAL_LOCKS,
  SUM(CASE WHEN LOCK_STATUS = 'HELD' THEN 1 ELSE 0 END) AS HELD,
  SUM(CASE WHEN LOCK_STATUS = 'WAITING' THEN 1 ELSE 0 END) AS WAITING
FROM QSYS2.OBJECT_LOCK_INFO
UNION ALL
SELECT 
  'Record Locks' AS LOCK_TYPE,
  COUNT(*) AS TOTAL_LOCKS,
  SUM(CASE WHEN LOCK_STATUS = 'HELD' THEN 1 ELSE 0 END) AS HELD,
  SUM(CASE WHEN LOCK_STATUS = 'WAITING' THEN 1 ELSE 0 END) AS WAITING
FROM QSYS2.RECORD_LOCK_INFO;
```

### 2. ロック競合の早期検出

```sql
-- ロック待機が発生しているジョブをアラート
SELECT JOB_NAME, 
       COUNT(*) AS WAITING_LOCKS,
       LISTAGG(OBJECT_SCHEMA || '.' || OBJECT_NAME, ', ') 
         WITHIN GROUP (ORDER BY OBJECT_NAME) AS OBJECTS
FROM QSYS2.OBJECT_LOCK_INFO
WHERE LOCK_STATUS = 'WAITING'
GROUP BY JOB_NAME
HAVING COUNT(*) > 5;  -- 5つ以上のロック待機
```
